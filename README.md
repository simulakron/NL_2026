# NL_2026

Индивидуальная работа: **20 программ на 20 разных языках программирования**. Пять тем, на каждую тему — по 4 программы. Специализированные библиотеки не используются — только стандартная библиотека каждого языка.

## Порядок работы

Каждая задача выполняется в отдельной Git-ветке.

Имя ветки:

`<номер темы>_task_<номер задачи>_<язык>`

Например:

`1_task_1_d`

Исходные файлы размещаются в папке соответствующей темы:

`<папка темы>/task_<номер>_<язык>/`

Каждая программа должна запускаться самостоятельно и демонстрировать выполнение поставленной задачи. Для реализации используются только возможности стандартной библиотеки соответствующего языка.

## Языки

D, Scala, Nim, Swift, Prolog, Haskell, Ada, Clojure, Kotlin, Perl, Lua, Groovy, Erlang, Elixir, Rust, Ruby, F#, OCaml, Julia, Zig.

# Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Параллельный подсчёт суммы элементов массива | D | `1_task_1_d` |
| 2 | Параллельный поиск максимального элемента | Scala | `1_task_2_scala` |
| 3 | Параллельное вычисление факториалов для набора чисел | Nim | `1_task_3_nim` |
| 4 | Параллельная обработка строк: подсчёт количества слов | Swift | `1_task_4_swift` |

### 1.1 D. Параллельный подсчёт суммы элементов массива

Программа получает массив чисел и разбивает его на несколько диапазонов. Каждый поток независимо вычисляет сумму элементов своего диапазона, после чего частичные результаты объединяются в одну общую сумму.

Количество потоков задаётся пользователем или определяется исходя из размера массива. Для сравнения программа также выполняет последовательный подсчёт и выводит время работы последовательного и параллельного вариантов, а также полученные суммы.

### 1.2 Scala. Параллельный поиск максимального элемента

Программа создаёт массив чисел и разделяет его на несколько частей. Каждая часть обрабатывается отдельной задачей или потоком, который ищет локальный максимальный элемент.

После завершения всех параллельных вычислений локальные максимумы объединяются, и определяется максимальное значение всего массива. Программа выводит найденный элемент, его позицию и сравнивает время последовательного и параллельного поиска.

### 1.3 Nim. Параллельное вычисление факториалов для набора чисел

Пользователь задаёт набор целых неотрицательных чисел. Для каждого числа необходимо вычислить факториал. Задачи распределяются между несколькими потоками, каждый из которых независимо выполняет вычисления для выделенных ему элементов.

Результаты собираются в исходном порядке и выводятся в консоль. Программа должна корректно синхронизировать доступ потоков к общей структуре результатов и не допускать конфликтов при записи.

### 1.4 Swift. Параллельная обработка строк: подсчёт количества слов

Программа получает набор текстовых строк и распределяет их между несколькими потоками. Каждый поток подсчитывает количество слов в выделенных ему строках.

После завершения обработки частичные результаты суммируются. В консоль выводится количество слов в каждой строке, общее количество слов и время выполнения последовательного и параллельного вариантов обработки.

# Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Рекурсивный обход дерева и поиск заданного элемента | Prolog | `2_task_1_prolog` |
| 2 | Рекурсивная сортировка слиянием | Haskell | `2_task_2_haskell` |
| 3 | Рекурсивное вычисление НОД и расширенного НОД | Ada | `2_task_3_ada` |
| 4 | Рекурсивное решение задачи о рюкзаке | Clojure | `2_task_4_clojure` |

### 2.1 Prolog. Рекурсивный обход дерева и поиск заданного элемента

Программа представляет дерево в виде набора фактов, описывающих узлы и их связи. Рекурсивный предикат выполняет обход дерева и проверяет значения посещаемых узлов.

Для заданного элемента программа определяет, существует ли он в дереве, и при необходимости выводит путь от корня до найденного узла. Обход должен выполняться рекурсивно без использования специализированных библиотек.

### 2.2 Haskell. Рекурсивная сортировка слиянием

Программа реализует алгоритм сортировки слиянием исключительно рекурсивными функциями.

Исходный список рекурсивно делится на две части, каждая часть сортируется отдельно, после чего две отсортированные последовательности рекурсивно объединяются в одну. Программа выводит исходный список, результат сортировки и может сравнивать количество операций или время работы с обычной сортировкой.

### 2.3 Ada. Рекурсивное вычисление НОД и расширенного НОД

Программа реализует алгоритм Евклида для рекурсивного вычисления наибольшего общего делителя двух целых чисел.

Дополнительно реализуется расширенный алгоритм Евклида, позволяющий найти такие коэффициенты `x` и `y`, что:

`a*x + b*y = gcd(a,b)`

Пользователь вводит два числа, после чего программа выводит НОД и найденные коэффициенты расширенного алгоритма.

### 2.4 Clojure. Рекурсивное решение задачи о рюкзаке

Программа решает классическую задачу о рюкзаке методом рекурсивного перебора. Для каждого предмета необходимо определить, брать его или не брать, учитывая его вес и стоимость.

В результате определяется максимальная стоимость набора предметов, который не превышает заданную вместимость рюкзака. Помимо максимальной стоимости программа выводит выбранные предметы и их суммарный вес.

# Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Ввод списка чисел, расчёт статистики и запись результата в файл | Kotlin | `3_task_1_kotlin` |
| 2 | Копирование текстового файла с подсчётом строк, слов и символов | Perl | `3_task_2_perl` |
| 3 | Работа с файлом: фильтрация строк по условию | Lua | `3_task_3_lua` |
| 4 | Интерактивный консольный журнал заметок с сохранением в файл | Groovy | `3_task_4_groovy` |

### 3.1 Kotlin. Ввод списка чисел, расчёт статистики и запись результата в файл

Пользователь вводит с консоли последовательность чисел. Программа вычисляет основные статистические характеристики: количество элементов, сумму, среднее значение, минимум и максимум.

Полученная статистика выводится в консоль и одновременно сохраняется в текстовый файл. При запуске можно предусмотреть ввод имени выходного файла.

### 3.2 Perl. Копирование текстового файла с подсчётом строк, слов и символов

Программа получает имена исходного и выходного файлов. Содержимое исходного текстового файла построчно копируется в новый файл.

Одновременно программа подсчитывает количество строк, слов и символов. После завершения копирования статистика выводится в консоль, что позволяет проверить результат обработки файла.

### 3.3 Lua. Работа с файлом: фильтрация строк по условию

Программа читает текстовый файл построчно и выбирает только те строки, которые удовлетворяют заданному условию, например содержат указанное слово или начинаются с определённого символа.

Пользователь задаёт имя исходного файла и условие фильтрации. Подходящие строки записываются в новый файл и дополнительно выводятся в консоль. Если исходный файл невозможно открыть, программа должна вывести понятное сообщение об ошибке.

### 3.4 Groovy. Интерактивный консольный журнал заметок с сохранением в файл

Программа предоставляет простой консольный интерфейс для работы с заметками. Пользователь может добавлять новые записи, просматривать существующие заметки, искать записи по ключевому слову и завершать работу.

Данные хранятся в обычном текстовом файле. При запуске программа загружает ранее сохранённые записи, а после добавления или изменения заметки обновляет файл.

# Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | TCP-сервер «Эхо»: сервер возвращает клиенту полученное сообщение | Erlang | `4_task_1_erlang` |
| 2 | TCP-сервер калькулятора: клиент отправляет выражение, сервер возвращает результат | Elixir | `4_task_2_elixir` |
| 3 | TCP-сервер для передачи текстового файла от сервера клиенту | Rust | `4_task_3_rust` |
| 4 | Простой TCP-сервер чата для одного клиента | Ruby | `4_task_4_ruby` |

### 4.1 Erlang. TCP-сервер «Эхо»

Программа состоит из TCP-сервера и клиента. Сервер ожидает подключения клиента, получает от него текстовое сообщение и отправляет обратно точно такое же сообщение.

Клиент позволяет пользователю вводить сообщения с консоли. Обмен продолжается до получения специальной команды завершения соединения. Сервер должен корректно обрабатывать подключение и отключение клиента.

### 4.2 Elixir. TCP-сервер калькулятора

Клиент подключается к серверу по TCP и отправляет арифметическое выражение, например `25 + 17`. Сервер разбирает выражение, выполняет вычисление и возвращает клиенту числовой результат.

Необходимо предусмотреть обработку основных арифметических операций и некорректных выражений. После каждого запроса клиент получает ответ от сервера и может отправить следующий запрос.

### 4.3 Rust. TCP-сервер для передачи текстового файла

Сервер хранит текстовый файл и ожидает подключения клиента. Клиент отправляет запрос на получение файла, после чего сервер передаёт его содержимое через TCP-соединение.

Клиент сохраняет полученные данные в локальный файл и сообщает размер полученного содержимого. Сервер должен корректно обрабатывать отсутствие файла, ошибки подключения и завершение передачи.

### 4.4 Ruby. Простой TCP-сервер чата для одного клиента

Сервер устанавливает TCP-соединение с одним клиентом и организует двусторонний обмен текстовыми сообщениями.

Клиент вводит сообщения с консоли, сервер принимает их и может отвечать собственными сообщениями. Работа продолжается до отправки команды завершения соединения. После отключения клиента сервер возвращается в состояние ожидания нового подключения.

# Тема 5. Конвертация данных

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|---|---|---|
| 1 | Конвертация CSV → текстовый формат с выравниванием столбцов | F# | `5_task_1_fsharp` |
| 2 | Конвертация JSON-подобного набора данных → CSV | OCaml | `5_task_2_ocaml` |
| 3 | Конвертация CSV → XML | Julia | `5_task_3_julia` |
| 4 | Конвертация INI-подобного формата → JSON-подобный формат | Zig | `5_task_4_zig` |

### 5.1 F#. Конвертация CSV → текстовый формат с выравниванием столбцов

Программа читает CSV-файл, содержащий строки с одинаковым количеством столбцов. Первая строка рассматривается как заголовок.

Полученные данные преобразуются в обычную текстовую таблицу. Для каждого столбца вычисляется необходимая ширина, после чего значения выравниваются таким образом, чтобы все строки образовывали аккуратные столбцы.

Результат выводится в консоль и сохраняется в отдельный текстовый файл.

### 5.2 OCaml. Конвертация JSON-подобного набора данных → CSV

Программа получает данные в упрощённом JSON-подобном формате, содержащем массив объектов с одинаковым набором полей.

Необходимо самостоятельно выполнить разбор входных данных без специализированного JSON-пакета, преобразовать объекты в строки CSV и корректно обработать значения строкового и числового типов.

Названия полей используются как заголовки CSV-файла, а каждый объект становится отдельной строкой таблицы.

### 5.3 Julia. Конвертация CSV → XML

Программа читает CSV-файл и преобразует его содержимое в XML-подобную структуру.

Первая строка CSV используется как набор названий полей. Каждая последующая строка превращается в отдельный XML-элемент записи, внутри которого находятся элементы соответствующих столбцов.

Результат записывается в XML-файл с корректным экранированием специальных символов в текстовых значениях.

### 5.4 Zig. Конвертация INI-подобного формата → JSON-подобный формат

Программа читает текстовый файл с секциями и парами `ключ=значение`. Секции задаются в формате `[section]`, а строки с комментариями должны игнорироваться.

Полученная структура преобразуется в JSON-подобный формат, где секции становятся вложенными объектами, а пары ключ–значение — свойствами этих объектов.

Результат форматируется с отступами и сохраняется в отдельный файл. Программа должна самостоятельно выполнять разбор входного формата и формирование выходного текста без использования специализированного парсера.
